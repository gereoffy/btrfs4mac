# btrfs4mac

Read-only btrfs support for macOS. The goal is an FSKit file system
extension (macOS 15+); the first part, implemented here, is a portable C
library that reads btrfs and a command line tool built on it.

## Status

| Part | State |
|------|-------|
| `libbtrfsro` C library | working, tested on the sample images |
| `btrfsro` command line tool | working |
| FSKit extension (`fskit/`) | working on macOS 15.7 (see notes below) |

## Scope

Supported:

* single device filesystems, SINGLE / DUP metadata and data (RAID1 family
  and RAID0 when every copy is on the one device)
* the default subvolume as root; other subvolumes show up as directories
* regular files (inline, regular, prealloc, holes, NO_HOLES), directories,
  symlinks, hardlinks, special files, extended attributes
* zlib, lzo and zstd compression
* crc32c, xxhash64, sha256 and blake2b checksums, all metadata verified,
  data checksums verified by default
* any sector size / node size from 4K to 64K

Not supported, by design: writing, multiple devices, RAID5/6, log tree
replay (fsynced changes after the last commit are not visible),
extent-tree-v2 and the raid stripe tree.

## Building

Xcode command line tools are enough:

    make            # build/libbtrfsro.a and build/btrfsro
    make fuzz       # build/fuzz, sanitizer-instrumented corruption fuzzer
    make test       # run tests/run-tests.sh

## The command line tool

    btrfsro [-v] [--no-verify] <command> ...

    info     <image>                      superblock information
    ls       [-l] [-R] <image> [path]     list a directory
    cat      [-o off] [-n len] <image> <path>
    stat     <image> <path>
    readlink <image> <path>
    xattr    <image> <path>
    extract  <image> <path> <destdir>     copy a file or tree out
    manifest <image> [path]               path/metadata/sha256 list
    extents  [-s] <image> <path>          file extent map

`<image>` can be an image file or a disk device (`/dev/rdiskNsM`, needs
read permission, e.g. via sudo).

Installing the library for other programs (static library, header and a
`btrfsro.pc` pkg-config file):

    make install PREFIX=/usr/local

The Midnight Commander fork at https://github.com/gereoffy/mc (branch
`vfs-btrfs`) uses it for a read-only `ubtrfs://` VFS, configured with
`--enable-vfs-btrfs`.

## Library API

See [core/include/btrfsro.h](core/include/btrfsro.h). The library does no
I/O by itself: the caller passes a read callback, so the FSKit extension
can read through its block device resource. All calls are thread safe after
mount.

## FSKit extension

`fskit/` contains the host app (`BtrfsMac`) and the FSKit module (`BtrfsFS`,
Swift, with the C library compiled in). The Xcode project is generated by
`fskit/gen-xcodeproj.py`.

Building and installing are separate steps, so the app can be built and
signed on one Mac and installed on another:

    TEAM_ID=ABCDE12345 NOTARY_PROFILE=notary fskit/build.sh   # on the signing Mac
    fskit/install.sh BtrfsMac.zip                              # on the target Mac

`fskit/build.sh` writes `fskit/dist/BtrfsMac.app` and `BtrfsMac.zip`. The
FSKit entitlement needs a provisioning profile, i.e. a paid Apple Developer
Program team that Xcode is signed in to; certificates and profiles are
created automatically. Modes (`MODE=`):

* `developer-id` (default with `TEAM_ID`): runs on any Mac; with
  `NOTARY_PROFILE` (see `xcrun notarytool store-credentials`) it is also
  notarized and stapled, so Gatekeeper accepts the downloaded zip.
* `development`: Apple Development signing, runs only on Macs registered in
  the team (Provisioning UDID: `system_profiler SPHardwareDataType`).
* `local` (default without `TEAM_ID`): no provisioning profile, only for
  testing the build.

`fskit/install.sh [BtrfsMac.app|BtrfsMac.zip]` needs no developer tools: it
copies the app to /Applications and registers the module. Then launch
`/Applications/BtrfsMac.app` once and enable "btrfs" in System Settings >
General > Login Items & Extensions > File System Extensions. btrfs disks
and attached images are then mounted automatically (read-only):

    hdiutil attach -readonly -imagekey diskimage-class=CRawDiskImage image.img
    umount /Volumes/btrfs

Notes from getting it running (macOS 15.7, Intel):

* The FSKit entitlement needs a provisioning profile, which personal (free)
  teams cannot get. With a paid Developer Program team, sign normally from
  Xcode. Without one, `build.sh` (`MODE=local`) signs with an "Apple
  Development" certificate (or ad hoc) and no profile; AMFI then refuses to launch the
  module ("Unsatisfied entitlements: com.apple.developer.fskit.fsmodule ...
  No matching profile found"). It runs only with the boot-arg
  `amfi_get_out_of_my_way=1`, which breaks other apps (Firefox crashes,
  Thunderbird slows down), so that is for a one-off test only.
* `mount -F -t btrfs` from Terminal does not work for third-party modules:
  fskitd only lets entitled clients (DiskArbitration) perform the final
  kernel mount. Attach the disk/image and let DiskArbitration mount it.
* `diskutil unmount` fails (StorageKit error 119); use `umount` or eject in
  Finder.
* If the home folder is not on the system volume, fskit_agent cannot save
  the "enabled modules" list (its sandbox denies the temporary file) and the
  switch in System Settings flips back. `install.sh` adds the module to
  `enabledModules.plist` in the FSKit settings group container directly.
* The module needs `FSActivateOptionSyntax` in its Info.plist, otherwise
  mount reports "does not support operation mount".
* Throughput is about 25 MB/s (every read goes through XPC on macOS 15).

Verified: the whole kernel test image read through the mounted volume gives
the same manifest (paths, types, modes, link counts, sizes, mtimes, inode
numbers, sha256 of every file, symlink targets) as the library.

## Layout

    core/include/btrfsro.h   public API
    core/src/                btrfs reader (derived from btrfs-fuse)
    core/vendor/zstd/        zstd decompressor (BSD)
    tools/btrfsro.c          command line tool
    fskit/                   FSKit module, host app, Xcode project generator
    tests/                   test suite, fuzzer, Linux helper scripts

## Origin

`core/src` started as a port of Qu Wenruo's
[btrfs-fuse](https://github.com/adam900710/btrfs-fuse) (MIT). Changes:
macOS port, I/O through a callback, single device volume code, hash table +
LRU tree block cache, structural validation of every tree block, bounds
checks on all item parsing, fixed LZO and inline compression bugs, own
MIT implementations of crc32c, blake2b, LZO1X and the list helpers (the
GPL-licensed `libs/` of btrfs-fuse is not used), parent lookup, xattrs.

## Testing

`make test` runs:

* known answer tests of all checksum algorithms
* the empty image `teszt-ures/btrfs-test.img`
* on `teszt-kernel/btrfs-test.img`: a full manifest (every file read and
  hashed), the kernel tarball inside the image decompressed and compared
  member by member (type, mode, mtime, size, sha256, link target) with the
  extracted tree, hardlink and symlink checks, `git fsck --full --strict` on
  the extracted `.git`, random offset reads against a sequential read
* every `tests/images/<name>.img` that has a `<name>.manifest` made on Linux
  is compared against it line by line
* corruption fuzzing: metadata blocks are mutated and their checksum
  recomputed, then the whole tree is walked under ASan/UBSan

More images (compression, checksum types, node sizes, holes, prealloc,
xattrs, special files, ...) can be produced on Linux with
`sudo tests/make-test-images.sh`; copy the results into `tests/images/`.
